# A tied file has an open gap

- **When:** A file tied both ways has an open gap, or its rule's wording changed.
- **Check it runs:** both halves of the tie removed together.
- **Detected by:** tie writer.

- The mechanical list always holds one standing item: "If a later step of this run finds an open gap in a file tied
  both ways, remove both halves of its two-way tie in the same commit: the rule's file line becomes 'needed', and
  the file's heading no longer states the rule's bold sentence."

A specific rule whose file still has an open gap gets no two-way tie. Its file line stays as it was, or becomes
"needed" under the standing item, and its file states no rule's bold sentence. The reason goes in the record, never
in a CLAUDE.md. The rule fails rule → file until it is tied, so it is an open item, with its reason code.

A rule whose wording the user changed: if its file was tied both ways, remove both halves of that two-way tie (the
standing item, above) until step 12 audits it again.
